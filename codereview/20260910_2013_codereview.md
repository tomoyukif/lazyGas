## Findings



### Critical



#### C1. ドメイン重なりが isoform をまたいで偽ヒットしうる

- **Where**: `.cursor/plans/phase2_E2_plan.md` §3.2; `phase2_E7_plan.md` §2.3
- **Plan ref**: 全 isoform 残し + `aa_pos` がいずれかの区間に入ればヒット
- **平易な説明**: 同じ遺伝子でも転写産物（isoform）が違うと、タンパク質の「何番目のアミノ酸」が違う。SnpEff が付ける位置はある isoform 基準なのに、InterProScan の区間は別 isoform のまま全部残すと、別物の地図を重ねることになる。
- **なぜ問題か**: 実際にはドメイン上に無いミスセンスが「ドメイン上の MODERATE」と見え、候補の優先度を誤る。逆に正しい isoform の区間だけ見れば当たるのに、別 isoform のズレで外れることもある。
- **Issue（技術詳細）**: ANN の transcript/protein ID と InterProScan 配列 ID の一致条件が無い。最悪 Impact をドメイン単位に畳むため、偽ヒットが叙述の主証拠になりやすい。
- **Evidence**: E7「全 isoform 残す」＋ E2「いずれかの区間」；GFF マップは Gene_ID までで transcript 一致を要求していない。
- **望ましい状態**: 重なり判定は **同じ protein/transcript ID 同士だけ**。一致できない変異–ドメイン対はスキップし、スキップ件数を coded に残す。
- **Impact**: ドメイン＝機能破壊の示唆として読まれやすく、GWAS/QTL 候補の解釈を歪める。
- **Recommendation**: E2/E7 を「同一 ID のみ重なり」に改定。一致率低下時は警告または InterProScan 拡張を無効化。
- **ユーザー方針**: （ここに記入）

  - 方針・修正案:E2/E7 を「同一 ID のみ重なり」に改定。一致率低下時（80%未満）は警告

#### C2. 行 Z（符号付き）行列に Yanai τ をそのまま使うと特異性の意味が壊れる

- **Where**: `.cursor/plans/phase2_E4_plan.md` §4, §5.2
- **Plan ref**: 特異性は scale によらず τ；相対高さだけ row_zscore で NA
- **平易な説明**: Yanai の τ は「発現量が 0 以上で、どこかで高く・他で低い」ような非負プロファイル向け。行ごとに平均 0・分散 1 にした値はマイナスを含み、同じ式でも「組織特異的」の古典的意味にならない。
- **なぜ問題か**: `summary: high` の τ を「葉特異的」と読むと、Z 正規化データの人工的な形を生物学と取り違える。
- **Issue（技術詳細）**: τ は通常 max で割る定義で非負を前提。負値やゼロ中心のまま状態平均すると、解釈不能または不安定。
- **Evidence**: E4 §1 表で τ は abundance/row_zscore とも可；§5.2 は高さのみ NA。
- **望ましい状態**: row_zscore では τ を出さない／非負変換後のみ τ とし、変換を JSON に明記する。
- **Impact**: Expression 枠の主指標が誤読される（E8 総括にも波及）。
- **Recommendation**: E4 を改定（Z では τ 禁止、または明示変換＋注意文）。
- **ユーザー方針**: （ここに記入）
  - 採否:採用
  - 方針・修正案:E4 を改定（Z では τ 禁止）、入力はZじゃなくてTPMやカウントを入力するように注意書き
  - 備考:



#### C3. QTL の「max_PIP」は遺伝子上の最大 PIP ではないのに、同じ名前で並べ替え・叙述に使う

- **Where**: `.cursor/plans/phase2_E_plan.md` §1.3; `phase2_E0_plan.md` §3.2; `phase2_E3_plan.md`
- **Plan ref**: GFF 窓中点に最近傍の CS マーカーの PIP を `max_PIP` と呼ぶ
- **平易な説明**: 名前は「その遺伝子に付いた PIP の最大」に聞こえるが、中身は「窓の真ん中に一番近い CS マーカーの PIP」。遺伝子から離れた高 PIP マーカーの値でも、その遺伝子が高く見える。
- **なぜ問題か**: `top_n` や E3 の「max_PIP が小さい／大きい」が、遺伝子のファインマップ支持の強さとして誤読される。GWAS モードの定義とも名前が衝突する。
- **Issue（技術詳細）**: 並べ替えキーと Gemma JSON が同一キー名。B2 の finemap（CS∩SnpEff の max）とも別物。
- **Evidence**: 親 §1.3 と E3 プロンプト草案の `max_PIP` 言及。
- **望ましい状態**: 列名を `nearest_cs_PIP` 等に変更。必要なら窓内 CS の真の max を別列で出す（無ければ NA）。
- **Impact**: 候補の優先順位と叙述の両方がずれる。
- **Recommendation**: 命名変更＋ E3/E8/並べ替えの文言修正。B2 finemap との対応表を親計画に書く。
- **ユーザー方針**: （ここに記入）
  - 採否:採用
  - 方針・修正案:列名を `nearest_cs_PIP`
  - 備考:（質問への回答）QTL ではピーク周辺マーカーは強く連鎖し、**関連統計（LOD / −log10P）**は山頂から裾野へなだらかに落ちることが多い。一方 **PIP（Wakefield ABF）は必ずしも同じく距離に沿って単調減少しない**。相関の強いマーカー間で「どの1点が信号を代表するか」の確率を分け合うため、CS 内ではピーク近傍でも PIP が低く、少し離れた CS マーカーが相対的に高い、といった**飛び石・共有**が起きうる。したがって「近い遺伝子ほど PIP もなだらかに低い」とは限らず、`nearest_cs_PIP` を遺伝子の支持度そのものと読まない（命名変更の理由そのもの）。

#### H2. 行 SD 中央値 ∈ [0.8, 1.2] だけで row_zscore 判定すると、量スケールを誤爆しうる

- **Where**: `phase2_E4_plan.md` §2.3

- **Impact**: Expression の高さと τ 経路の両方が誤分岐。
- **Recommendation**: override を計画に戻す。誤爆時の安全側を明記。
- **ユーザー方針**: （ここに記入）
